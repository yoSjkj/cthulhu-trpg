# 아키텍처

## 역할 분리

| 주체 | 담당 |
|---|---|
| 룰 엔진 (`src/engine/`) | 주사위, 판정, 수치 계산, 생사 판정 |
| 게임 상태 (`src/store/`) | 캐릭터, 진행 상태, 영속화 |
| AI 키퍼 (`src/api/`) | 묘사, 선택지 제시, 판정 필요 여부 신호 |
| UI (`src/pages/`) | 흐름 제어, 사용자 입력 |

**AI는 수치를 계산하거나 변경하지 않는다.**
AI는 "판정이 필요하다"는 신호만 보내고, 결과는 코드가 계산해 AI에 전달한다.

## AI 응답 검증

AI 응답은 신뢰하지 않는다. 다음은 반드시 코드가 검증한다.

| 필드 | 검증 내용 |
|---|---|
| `move_to` | 현재 장소의 `connections`에 포함된 id인가 |
| `trigger_ending` | `endings`에 존재하는가 / `requires_ritual` 조건이 충족됐는가 |
| `hp_loss.formula` | 허용 목록에 있는 주사위 식인가 |
| `requires_check.skill` | 알려진 기술명·능력치명인가 |
| 전체 응답 | 필수 필드가 모두 존재하는가 (없으면 기본값 채움) |

프롬프트로 지시하는 것은 검증이 아니다. 지시는 새어나간다.

## 데이터 흐름

플레이어 행동
→ AI 키퍼 호출 (현재 상태 + 컨텍스트 전달)
→ AI 응답 파싱 및 검증
→ 판정 필요 시: 코드가 주사위 굴림 → 결과 계산
→ 상태 갱신 (HP, SAN, 단서, 위치)
→ 결과를 컨텍스트로 담아 다음 AI 호출

각 단계의 수치 변경은 반드시 엔진 함수를 경유한다.

## 모듈 규칙

**`src/engine/`**
- 순수 함수만. React, fetch, localStorage 의존 금지
- 부작용 없음. 입력에 대해 결정론적이어야 한다 (RNG는 주입)
- 시나리오 내용을 하드코딩하지 않는다

**`src/api/`**
- LLM 프로바이더 의존을 어댑터 한 곳에 격리한다
- 프롬프트 조립과 응답 파싱만 담당. 게임 로직 금지

**`src/store/`**
- Zustand + persist. 스키마 변경 시 `version`과 `migrate`를 갱신한다
- 세션 재개에 필요한 모든 상태를 여기 둔다
  (대화 히스토리, 요약, 전투 상태, 광기 잔여 턴 포함)

**`src/pages/`**
- 흐름 제어만. 룰 계산을 여기서 하지 않는다
- 룰 로직이 필요해지면 `engine/`으로 옮긴다

## 난수

모든 주사위는 `dice.js`를 경유한다.
`dice.js`는 주입 가능한 RNG를 노출하며, 테스트는 이를 고정해 결정론적으로 검증한다.
`Math.random()` 직접 호출은 금지한다.

## 프롬프트 구성

시스템 프롬프트는 두 부분으로 나눈다.

1. **정적** — 룰, 톤 가이드, 응답 형식, 시나리오 기본 정보
2. **동적** — 탐사자 상태, 현재 장소, 정신 상태, 전투 상황

정적 부분을 앞에 두어 프롬프트 캐싱이 가능하게 한다.

## 정보 공개

AI 키퍼에게 시나리오 전체를 주지 않는다.

- 현재 장소와 인접 장소만 전달
- 이미 공개된 단서 + 현재 장소의 미공개 단서만 전달
- `visible_from_start: false`인 장소는 도달 전까지 전달하지 않는다

키퍼가 결말을 미리 알면 묘사에 새어나간다.

## 테스트

- `src/engine/`은 단위 테스트 필수. 경계값 중심
- AI 응답 파싱·검증은 고정 입력으로 테스트한다
- 룰 값 변경 시 대응 테스트가 함께 변경되어야 한다
